# Baseline Reproducer Skill

中文 | [English](README.en.md)

一个用于审计和复现已发表 ML/AI 基线的证据门控 Agent Skill。

```text
工件审计 → checkpoint 冒烟测试 → evaluator 回放 → checkpoint 指标复现
→ 训练冒烟测试 → 完整训练复现
```

本 Skill 严格区分部署、推理、评测器、公开权重和训练流程的证据，并将证据充分的停止决定视为有效结果，而不是强行补齐缺失信息。

## 安装

将 `baseline-reproducer/` 复制或软链接到 Codex、Claude Code、Cursor 或其他兼容 Agent Skills 客户端的 Skill 目录。

```bash
mkdir -p ~/.codex/skills
ln -s "$(pwd)/baseline-reproducer" ~/.codex/skills/baseline-reproducer
```

然后可以这样调用：

> 使用 `$baseline-reproducer` 审计这篇论文的官方工件，并复现其公开材料能够支持的最强主张。

## 主要原则

- 优先运行官方代码、公开权重和官方评测器，而不是从论文重新生成实现；
- 将论文拆成原子主张，分别记录证据等级；
- 区分 [evaluator replay](#evaluator-replay)、checkpoint 指标复现和完整训练复现；
- 固定代码 revision、权重 hash、数据 split、seed 和评测协议；
- 保留失败运行、兼容性修改、资源干扰和被作废的结果；
- 缺少关键数据、权重或协议时明确停止，不做未经标注的替代；
- 在公开权重验证通过且训练 Gate 完整后，才启动昂贵训练。

## 论文指标的链路完整度评级

评级对象不是整篇论文，而是论文表格中的一个<strong>原子指标主张</strong>。例如：

| 模型 | 数据集 1 | 数据集 2 |
|---|---:|---:|
| SOTA1 | a1 | a2 |
| Ours | b1 | b2 |

这里共有四个主张：

- `b1`、`b2` 是论文对自身模型作出的两个<strong>本模型主张</strong>；
- `a1`、`a2` 是论文引用或重新测量的两个<strong>其他模型主张</strong>。

一篇论文可能包含许多实验表格。通常先选择最重要的若干表格，例如主结果、关键消融和核心泛化实验，再将其中每个关键单元格登记成独立主张。不要用一个总评级覆盖整篇论文。

<sub>消融实验按复现成本排序：若需要增删模型模块、重新训练或重新发布权重，通常优先级低于主结果；若只需改变测试时设置、推理参数、输入条件或 evaluator 开关，且可以复用同一公开权重，则属于低成本、可控的消融，可优先验证。任何测试时变更仍须单独冻结协议，不能与主结果混成同一条指标链路。</sub>

### 两类、四个独立评级

每个主张分别记录：

1. <strong>交付完整度</strong>：作者公开了什么。
   - <strong>TD（Test Delivery Completeness，测试交付完整度）</strong>：作者是否交付了验证该数值所需的权重、测试代码、测试数据及划分和评测协议。
   - <strong>RD（Training Delivery Completeness，训练交付完整度）</strong>：作者是否交付了产生该权重所需的训练代码、训练数据及划分、训练设置和依赖权重。
2. <strong>复现完整度</strong>：复现者实际验证到哪里。
   - <strong>TR（Test Reproduction Completeness，测试复现完整度）</strong>：复现者是否实际运行并审计了权重到指标的测试链路。
   - <strong>RR（Training Reproduction Completeness，训练复现完整度）</strong>：复现者是否实际运行并审计了数据到训练权重再到指标的完整链路。

交付评级描述“作者公开了什么”；复现评级描述“复现者实际验证到哪里”。四个评级不能互相替代。

### 等级定义

四个指标分别评级，不能用一张通用表互相推导。基础等级从低到高为 `F`、`I`、`M`、`E`、`O`；其中 `M+` 和 `E+` 用于标记已明显超过本级基本要求、但尚未达到下一基础等级的情况。标签沿用“Failed / Improving / Medium / Excellent / Outstanding”的分级命名[[1](https://www.zhihu.com/question/495085246), [2](https://www.dingteam.com/article/285)]，这里衡量的是<strong>公开材料和实际复现为该主张数值提供了多强的可核查证据</strong>：评级会影响我们对该数值的可信程度，但不评价数值本身的高低，也不延伸为对整篇论文总体可信度的评级。`NR`（Not Rated / Not Applicable）表示尚未评级或不适用，不属于上述等级。

以下定义均按单个已冻结主张判定。例如，`Paper X` 表 1 中“模型在 `Dataset 1` 上得到 `b1=82.7`”是一条主张；同一论文中的其他单元格应分别评级。

#### TD：测试交付完整度

按公开材料所能支持的<strong>最高等级</strong>评级，并采用“关键短板决定等级”的原则：不能用若干完整项目抵消 checkpoint 身份、测试集划分或评测规则等关键缺口。

| 等级 | 定义 | 示例（`Paper X / b1=82.7`） |
|---|---|---|
| **O** | 完整给出运行环境及版本号；可获取与目标主张准确对应的模型权重，以及论文使用的测试集及其精确划分；公开全部测试参数；测试规则（数据预处理、推理、评测、聚合及随机性处理等）清晰完整，无须猜测或替换任何影响结论的设置。 | 作者提供 `environment.yml`，其中指定 Python 3.10.13、PyTorch 2.1.2 和 CUDA 12.1；表 1 明确对应 `paper-x-step-50000.ckpt`，并给出 SHA-256；`test_ids.txt` 列出用于评测的 10,000 个样本 ID。测试命令指定 `seed=42`、`batch_size=64`，图像先缩放到 256 像素再做 224×224 中心裁剪；最后用随仓库发布的 `accuracy.py` 计算全部样本的 top-1 accuracy，得到论文所报的 `82.7`。 |
| **E** | 从对应 checkpoint 到论文指标的主要材料和规则均已交付，仅需少量可追溯的确定性重建或兼容处理；这些处理不改变模型、数据、参数或评测含义。<br><strong>可评为 E+：</strong>checkpoint、测试集及划分、测试参数和测试规则均完整且与目标主张准确对应，复现者无须自行决定任何影响结论的设置；只缺硬件型号、启动命令示例或非关键依赖版本等操作性信息。 | **E：**作者提供 `paper-x-step-50000.ckpt`、`Dataset 1 v2.1` 和 `make_test_ids.py`；运行该脚本可从公开元数据固定生成同一份 10,000 样本列表。评测代码中的旧参数 `torch_device="cuda"` 需等价改为 `device="cuda"`。<br>**E+：**作者直接提供上述 checkpoint、10,000 个样本 ID、`seed=42`、224×224 中心裁剪规则和 `accuracy.py`，但没有说明使用的是 A100 还是 H100，也未给出完整启动命令。 |
| **M** | 已交付部分可执行测试链路，但存在重要缺口。可能只能进行单样本测试或 [evaluator replay](#evaluator-replay)；也可能可以完成全量测试，但 checkpoint 版本、测试集划分、关键推理参数、evaluator 或聚合规则不能与论文严格对齐。所得结果不能直接等同于论文原指标。<br><strong>可评为 M+：</strong>能够组成完整的 checkpoint 到指标链路，模型权重、测试集和评测方法基本对应目标主张，只缺原始 seed、精确依赖版本、次要测试参数或统计细节等一项非核心设置。 | **M：**作者只发布 `table1_predictions.json` 和 `accuracy.py`；把其中 10,000 条预测送入脚本可以重算 `82.7`，但没有发布生成这些预测的 checkpoint。另一种情况是 `paper-x.ckpt` 可以完成全量测试，但仓库同时包含 `test-v1.txt` 和 `test-v2.txt`，论文没有说明使用哪一份。<br>**M+：**作者发布 `paper-x-step-50000.ckpt`、`test_ids.txt` 和 `accuracy.py`，并指定 224×224 中心裁剪和 `batch_size=64`，但没有公开原始 seed；复现者必须在运行前自行固定 seed。 |
| **I** | 只能找到论文数值、仓库、权重链接、数据入口或零散代码；关键工件严重缺失或彼此无法对应，尚不能组成可执行的主张级测试链路。 | 仓库只提供名为 `model_final.ckpt` 的权重链接，没有配置文件或表格映射说明它是否对应表 1；`Dataset 1` 官网有多个测试划分，仓库既未指定其中一个，也没有提供评测命令。 |
| **F** | 已确认公开工件与目标主张冲突，例如权重属于另一模型变体、测试集使用另一划分，或评测协议被替换；这些材料即使能够运行，所得结果也不能归属于目标主张。 | 下载页把 `paper-x-large.ckpt` 标为表 1 权重，但其配置显示 `hidden_size=768`，而表 1 的 Large 模型应为 `hidden_size=1024`；因此该权重的测试结果不能归属于 `b1=82.7`。 |

#### RD：训练交付完整度

| 等级 | 定义 |
|---|---|
| **O** | 完整给出运行环境及版本号、训练代码与配置；可获取论文使用的训练数据及其精确划分、依赖权重和初始化材料；公开全部训练参数，以及停止条件和 checkpoint 选择规则；训练规则（数据预处理、采样、优化、分布式训练及随机性处理等）清晰完整，无须猜测或替换任何影响结论的设置。 |
| **E** | 从训练数据到目标 checkpoint 的主要材料和规则均已交付，仅需少量可追溯的确定性数据重建或兼容处理；这些处理不改变模型、数据、参数或训练含义。<br><strong>可评为 E+：</strong>训练数据及划分、代码、完整配置、依赖权重、训练参数和 checkpoint 选择规则均完整且与目标主张准确对应；复现者无须自行决定任何影响结论的设置，只缺硬件型号、启动命令示例或非关键依赖版本等操作性信息。 |
| **M** | 已交付部分可执行训练链路，但关键材料或设置存在缺口；可能只能完成数据加载、短步数训练或训练子集 smoke test，也可能能够完整训练，但数据版本/划分、初始化权重、关键超参数、停止条件或 checkpoint 选择规则不能与论文严格对齐。<br><strong>可评为 M+：</strong>能够组成完整的数据到 checkpoint 训练链路，模型、主要数据和训练方法基本对应目标主张，只缺原始 seed、精确依赖版本、次要超参数或统计细节等少量不妨碍链路闭合的信息。 |
| **I** | 只有论文描述、零散训练代码或数据入口；训练数据、划分、关键依赖权重、配置或训练入口严重缺失，尚不能组成可执行的目标训练链路。 |
| **F** | 已确认训练工件与目标主张冲突，例如代码或配置属于另一模型、训练数据使用另一版本，或训练协议被替换；所得 checkpoint 不能归属于目标主张。 |

#### TR：测试复现完整度

| 等级 | 定义 |
|---|---|
| **O** | 在版本明确的干净环境中，使用与目标主张准确对应的 checkpoint 和测试集划分，按完整测试参数与规则完成端到端全量测试；完成完整性检查、必要的重复运行或不确定性分析，并保留逐样本结果、命令、日志、哈希和全部偏差，第三方可直接复核。 |
| **E** | 已冻结 checkpoint、测试集划分、测试参数和聚合规则，完成全量运行与完整性检查，并保留逐样本结果；仅有少量不改变测试含义的可追溯兼容处理。<br><strong>可评为 E+：</strong>在此基础上完成预先规定的重复运行或不确定性分析，并独立复核聚合结果和关键工件身份；仅未达到干净环境端到端重建或第三方直接复核所需的完整证据水平。 |
| **M** | 已执行部分有效测试链路，或已完成全量测试但关键条件无法与论文严格对齐；例如只完成单样本推理或 evaluator replay，或者使用独立 seed、替代版本或不完整统计设置。<br><strong>可评为 M+：</strong>已按基本对齐的协议完成对应 checkpoint 的全量测试并保留结果，只缺少量对严格对齐有影响的信息，或尚未完成必要的重复运行/不确定性分析。 |
| **I** | 已完成材料审计或尝试运行，但测试链路仍被关键工件、配置或执行错误阻塞，尚未得到可用于判断目标主张的有效结果。 |
| **F** | 已确认实际运行使用了错误 checkpoint、测试集划分或评测协议；结果已经作废，不能归属于目标主张。 |

#### RR：训练复现完整度

| 等级 | 定义 |
|---|---|
| **O** | 在版本明确的干净环境中，使用与目标主张准确对应的数据、模型配置和训练规则完成端到端训练与全量测试；完成必要的多次独立训练或不确定性分析，并保留数据谱系、命令、日志、中间 checkpoint、资源消耗、哈希和全部偏差，第三方可直接复核。 |
| **E** | 已冻结训练数据及划分、模型配置、训练参数、依赖权重、停止条件和 checkpoint 选择规则，完成端到端训练、全量测试及训练轨迹审计；仅有少量不改变训练含义的可追溯兼容处理。<br><strong>可评为 E+：</strong>在此基础上完成预先规定的多次独立训练或不确定性分析，并复核数据、checkpoint 和聚合身份；仅未达到干净环境完整重建或第三方直接复核所需的完整证据水平。 |
| **M** | 已执行部分有效训练链路，或已完成一次训练与评测但关键条件无法与论文严格对齐；例如只完成短步数训练或训练子集 smoke test，或者数据、seed、规模、超参数或停止规则存在重要差异。<br><strong>可评为 M+：</strong>已按基本对齐的协议完成一次端到端训练与全量测试，只缺少量对严格对齐有影响的信息，或尚未完成重复训练/不确定性分析。 |
| **I** | 已完成材料审计或尝试训练，但仍被关键数据、配置、依赖或资源问题阻塞，尚未产生可用于完整评测的有效 checkpoint。 |
| **F** | 已确认实际训练使用了错误数据、模型配置或训练协议；所得 checkpoint 与结果已经作废，不能归属于目标主张。 |

高等级不要求结果接近论文值。在完全固定的协议下稳定得到与论文不一致的结果，仍可能具有 `TR-E+` 或 `TR-O`，同时数值结论记为 `not_matched` 或 `contradicted_under_pinned_protocol`。反之，只因本地数字接近论文值，不能获得高评级。

### 示例评级

假设对上述主结果表审计后得到：

| 主张 | 类型 | TD | RD | TR | RR | 数值结论 |
|---|---|:---:|:---:|:---:|:---:|---|
| `b1` | 本模型 | E | M+ | E+ | M | matched |
| `b2` | 本模型 | M | I | M | NR | not_strictly_comparable |
| `a1` | 其他模型 | M | NR | M | NR | author_table_only |
| `a2` | 其他模型 | F | NR | F | NR | invalidated |

- **`b1`：** 精确权重、测试集和 evaluator 均公开并已复现；训练数据需按公开脚本重建，但尚只完成训练子集。
- **`b2`：** 权重公开，但作者未给 seed 和完整测试划分；训练数据未公开。只能报告固定独立协议结果。
- **`a1`：** 本文没有重新运行 SOTA1，只引用其原论文数值；可回到 SOTA1 原论文继续单独评级。
- **`a2`：** 论文使用的 SOTA1 数据划分与本表 Ours 不同，却放在同一列直接比较，该比较链路无效。

对于其他模型主张，要进一步记录数值来源：`cited_from_original_paper`、`rerun_by_current_authors` 或 `unclear`。只有当前论文确实使用同一协议重新运行了对方模型，`a1/a2` 才能直接继承当前表格的测试链路；单纯转抄原论文数字不能视为本文完成了复现。

## 证据包

默认结构包括：

```text
case/
├── REPRODUCTION_CARD.md
├── claim.json
├── source_manifest.jsonl
├── protocol.json
├── run_manifest.jsonl
├── reported_vs_reproduced.json
├── training_gate.json
├── commands.sh
├── patches/
├── logs/
└── outputs/
```

其中运行记录采用追加式保存，不覆盖失败或被作废的历史证据。

## 来源

该工作流提炼自一项长期论文复现实践，涉及公开视频生成 checkpoint、评测器、公开数据集和多 GPU 执行路径。Skill 泛化了其中关于身份冻结、协议分 lane、输出完整性审计、评测器回放、非覆盖式证据、结果作废和拒绝实质性协议替换的经验。

仓库不包含私有模型工件、凭证、机器路径或实验数据。

<a id="evaluator-replay"></a>
<strong>Evaluator replay（评测器回放）</strong>就是用作者公开的输出和评测代码，重新计算论文中的分数。例如，作者公开了 1,000 个生成视频和 VBench 代码；我们重新评分得到 `81.0`，论文也报告 `81.0`。这只能说明评分流程可以复现，不能说明模型生成或训练过程可以复现。

<a id="api-call"></a>
<strong>修改 API 调用</strong>是为了适配新版依赖，只更换已经失效的函数名、参数名或调用写法。例如把旧参数 `torch_device="cuda"` 改成新版参数 `device="cuda"`；传入值和实际计算不变。

<a id="independent-seed"></a>
<strong>复现者自行选用的 seed</strong>是指作者未公开原实验的随机种子时，复现者自己选择一组种子，例如 `42、43、44、45、46`。这些种子应在运行前固定并记录，避免看到结果后只挑表现好的种子。由于它们不是作者原来的种子，不能称为精确恢复作者实验。

<a id="protocol"></a>
<strong>协议（protocol）</strong>是产生并计算这个指标时使用的一整套固定设置，例如测试集划分、输入预处理、推理步数、seed、样本数和评分方法。只把旧 API 参数名改成新名称不算改变协议；改用另一份测试集或不同推理步数则算。
